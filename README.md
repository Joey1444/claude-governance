# Claude Code 规则治理模板

一套让 Claude Code **少试错、少烧 token、行为可预测**的规则治理体系。

不是「我的配置备份」，是「如何治理你的 Claude Code」的方法论 + 可复用零件。

## 为什么你需要它

Claude Code 默认状态是「无记忆、每次从零开始」。你的偏好、你的坑、你的取舍，每次会话都要重新教一遍——这就是反复调试烧 token 的根源。

这套模板把三样东西结构化：

| 机制 | 解决什么 | 省 token 的方式 |
|---|---|---|
| **判定表**（rules/file-responsibility） | 内容该放哪、职责怎么分 | 不用每次纠结，一次定死 |
| **精简铁律**（「删了会犯错吗？」） | 配置越攒越臃肿 | 每次加载的配置少了 |
| **hook 硬约束** | 「靠自觉」变成「硬拦」 | 不用靠模型每次自我提醒 |

## 目录结构

```
rules/      9 个主题规则（判定表、代码审查、编码纪律、上下文管理…）
agents/     6 个隔离副手（code-reviewer、security-reviewer…）
hooks/      1 个硬约束示例（写 memory 前强制判层级）
CLAUDE.md   全局规则模板（填空即用）
examples/   一个真实用户填满后的完整示例
```

## 快速开始

1. 先看 `CLAUDE.md`（模板）和 `examples/CLAUDE.md.example`（真实例子），理解「全局总则」长什么样。
2. 看 `rules/file-responsibility.md`——这是整套体系的**地基**，其他规则都靠它定位。
3. 按 `INSTALL.md` 把 rules/agents/hooks 装进你的 `~/.claude/`。
4. 把 `CLAUDE.md` 模板填成你自己的。

## 核心思想（为什么这套能工作）

**「移除这条会犯错吗？不会就删」**——这是整套体系的唯一判据。它逼你只留「换会话后还需要、且删了会犯错」的东西。

配合三条配套规则：

- **外科手术式改动**：只动任务相关的行，不顺手重构
- **验证优先**：永远不无证据声称成功
- **犯错就固化**：非平凡模式固化成规则，别只修这一次

## Skill 治理：只留必须的、可调用的

每个 skill 的 description 每轮对话都占上下文（不管用不用）。判据：

- **必须的**：有真实使用场景，删了会犯错
- **可调用的**：触发词语义能匹配你的用语——否则是死重，占 token 不产出

用 `/skill-doctor`（或调用频率统计）把「0 调用 + 无场景」的删掉。这是「移除这条会犯错吗」铁律在 skill 上的直接应用。

## 注意

- 本仓库**不含任何密钥**。你自己的密钥放 `~/.claude/token.txt` 并 gitignore（见 INSTALL.md）。
- 第三方 skill 和 plugin（如 superpowers、n8n-skills）**不打包**，各自从市场装，见 INSTALL.md。skill 该不该留，用下面的治理判据筛。
