# 上下文与 token 管理

- 只读必要文件片段，不反复读同一文件；能 grep 定位就不整读。
- **大文件判「体积」不判「份数」**：读体积未知的文件 / 转录 / 落盘 tool-results 前先看大小（ls -la 或 wc -c），超 ~20KB 或行数未知 → 交子 agent 只回摘要。历史会话转录（list_events 等）一律走这条——「只有一份」不是自己读的理由。
- 成本 = 进入上下文的字节 × 之后的轮数；久置后首条会全量重算（cache miss），故保持前缀稳定、别频繁改动已读内容。
- 走错方向用 /rewind（双击 Esc）回退，别打字纠错——别让失败回合留在上下文。
- 输出只留结论与关键证据，不塞大段命令输出、不长篇总结。
- 上下文变长或要切换任务时，用 /compact <hint>（带意图）或 /clear，别等自动压缩。

## 外部查询（WebSearch / WebFetch / MCP）
- 按类型选源，不按「本地 vs 网络」：本实例事实（credential / 节点 / 版本）→ MCP，**禁上网**；节点参数 / 最佳实践 → 已装 skill；都没有或需最新 → 官方源；论坛最后。
- 本地文档可能滞后于目标版本，版本不符就降权，以线上官方为准。
- 搜前先能写出「答案长什么样」，写不出就别搜（反复拆查的根因）。
- 大范围 / 多源调研交给子 agent（主会话只收摘要；琐碎调研指定小模型如 haiku）；答案小且直接就自己查——子 agent 不免费。
- **别从主对话扇出多个 agent**：N 个子任务就派 N 个 agent，会有 N 份报告堆进主对话。正确做法是**派一个总控 agent，让它在自己下面用 Agent 工具 spawn worker**（嵌套 delegation ≤3 层，主对话只收一条摘要）。总控的 tools 用 `Agent(worker_type)` 白名单限制它只能 spawn 特定类型；链式依赖走 handoff（一个 agent 的输出喂给下一个）。批量任务（分段翻译、批量改写、多文件审查）一律走这条。
- WebFetch 只问要的字段；能取 raw / JSON / 官方 markdown 就不抓渲染 HTML。
- 固化事实带版本 + 日期 + 来源层级。
