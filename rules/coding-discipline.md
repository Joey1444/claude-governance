# 编码纪律

## 想清楚再写
- 有歧义就明说假设；能自己查的先查，别用提问代替检索。

## 简单优先
- 只写解决问题的最小代码，不加没要求的特性/抽象/配置项。
- 不替外部输入臆造错误分支；但 Zod 校验与 try-catch 收窄照旧。
- 依赖外部字段做匹配/过滤时，别假设它一定有值——关键路径要有兜底（多字段匹配、默认值）。

## 外科手术式改动
- 只动任务相关的行，匹配现有风格；不顺手重构/重排/删无关代码。
- 只清理本次改动造成的 orphan（未用 import/变量）；历史遗留问题单列，不顺手清。
- 文档/注释/状态与代码或事实矛盾时，那是缺陷不是风格——先定严重级顶格报出，等确认再改。

## 目标驱动
- 把祈使句转成可验证的成功标准，循环到达标为止。
