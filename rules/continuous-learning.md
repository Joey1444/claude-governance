# 持续学习（犯错就固化）

- 发现非平凡模式（调试技巧、workaround、项目约定、踩过的坑）时，主动固化成 skill 或 memory，别只留在本次对话。
- 用户点破「你没想到 X」= 你在某类问题上模式失明，不是这次没看清——先问「换个场景会不会还犯」，会就固化成规则，别只修这一次。
- 固化格式：场景 / 正确做法 / Gotchas / 验证方式。
- **触发条件用具名枚举**（命令、版本号、字段名、文件路径），别用需自我判断的抽象词（"不熟悉的事""重要的事"）——抽象词不会触发。
- **固化前先验证归因**：没证明的因果推断只能写成「推测（未验证）」，不许沉淀成 memory/规则里的"经验"。错的事实比重试更贵——下次会照着错的因果去行动。
- 用户说"记住这个 / 固化 / 学一下"时，直接执行固化，不要只口头答应。
- 项目成功/告一段落后及时复盘：多角度审查（拉团队批判）、提炼真正值得上升全局的经验——宁缺毋滥，只升换场景仍适用的通用原则。（清理交给 task-closure.md）
