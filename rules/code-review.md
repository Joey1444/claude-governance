# 代码审查标准

## 何时必须审查
- 写完/改完代码后，尤其跨多文件的改动。
- 提交到共享分支前。
- 改动安全敏感代码时（见下方安全触发）。
- 架构级改动时。

## 审查清单
- 逻辑错误、边界情况、错误处理
- 性能（N+1、缺分页、无界查询）
- 可维护性（函数 <50 行、文件 <800 行、嵌套 <4 层、无 console.log）
- 新功能有测试

## 安全审查触发（用 security-reviewer agent）
auth/authz、用户输入、数据库查询、文件系统操作、外部 API 调用、加密、支付、密钥。

## 严重级别
| 级别 | 含义 | 动作 |
|---|---|---|
| CRITICAL | 安全漏洞或数据丢失 | 必须改，否则不合并 |
| HIGH | bug 或显著质量问题 | 应改 |
| MEDIUM | 可维护性 | 建议改 |
| LOW | 风格/小建议 | 可选 |

## 输出
按文件分组、按严重级排序；每条给 file:line + 问题 + 修复建议，不只指出问题。
